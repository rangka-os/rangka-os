# S11 Web Ubah mode and live preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People with change-set rights rearrange and extend the end-user app in an "Ubah" mode; every edit is a change set (low risk applied with one-click undo, medium/high pending with dry run), and the kernel serves a read-only preview of any pending change set.

**Architecture:** Kernel: new overlay keys and site dashboards in schema 0.5 (merged at load, checked identically by the Go and Python validators), a risk tweak (views-only overlays and site dashboards are low), `meta.changesets` capabilities, and `/api/v1/preview…` handlers that build a registry from the change set's sandbox copy and answer reads through a throwaway engine on the live database. App: `api.js` gains change-set and preview calls; a new `ubah.js` holds the pure op builders and the Ubah UI (toggle, edit affordances, undo toast, change-set card, preview banner) that the dashboard, form, list/kanban and shell views mount.

**Tech Stack:** Go 1.24 kernel, PostgreSQL 16, strict-YAML `.rk` + JSON Schema 2020-12, Python reference validator, React 18 UMD (no build), `node --test`, Playwright (Python) via `web/app/test_app.py`.

**Spec:** `docs/superpowers/specs/2026-11-03-first-pilots-design.md` (Decided → Rangka Cloud builder), program plan `docs/superpowers/plans/2026-11-03-pilot-program.md` (S11), and the fixed interface for this stream: `docs/contracts/0015-ubah-mode-and-live-preview.md` (read it first; every name below comes from it).

## Global Constraints

- Code, comments, docs in English; UI text Bahasa Indonesia first, sentence case, "kamu".
- `.rk` is strict YAML; files the app creates start with `# yaml-language-server: $schema=https://rangka-os.github.io/rangka-os/schema/0.5/<kind>.json`.
- Change sets are the only way runtime changes happen; approve only from `previewed`; high risk = owner only; AI tokens never approve, apply unapproved or revert.
- Company changes are overlays in `site/custom/<model>.rk` with `x_` fields, never edits to existing `apps/` files.
- `make -C kernel test` and `make -C kernel compare-python` stay green; Go and Python validator output byte-identical.
- App works from 400px (phone) to desktop; controls ≥ 40px tall on phones; no horizontal page scroll.
- Design: Ink `#1C1917` primary buttons, Bata `#A33B23` links/selection, focus `#E0623F`; use the design system (`window.Rangka`) components.

## Review Focus

- **A low-risk edit by an approver whose change set fails to validate** (e.g. a stale form layout naming a removed field): no apply, the card shows the validation errors; nothing on screen pretends it was saved. Test in Task 6 (`ubah.test.js` flow with a mocked invalid validate) .
- **Undo after someone else changed the same file** (two people in Ubah): revert restores the previous text of that change set only; the app reloads meta after undo. Kernel already tests revert; Task 6 tests that the undo reloads meta and shows the restored order.
- **Previewing a change set that adds a table or a column that does not exist in the database yet:** preview lists no records / omits the field instead of 500. Test in Task 3 (`TestPreviewNewModelAndField`).
- **A sales_rep (no change-set rights) opening `#/…?ubah=1`:** no toggle, no Ubah UI, no proposals. Test in Task 7 (`test_ubah_hidden_for_rep`) and Task 3 (`meta.changesets.propose == false`).
- **Writes while previewing** (a POST/PATCH under `/api/v1/preview/`): 405 `preview_read_only`; the app hides write buttons in preview. Test in Task 3 (`TestPreviewReadOnly`) and Task 6.

### Task 4: `api.js` change sets and preview mode

**Files:** Modify `web/app/api.js`, `web/app/test/api.test.js`.

**Interfaces — Produces on the api object:**
`changesets({status})`, `changeset(id)`, `propose({title, reason, ops}) → cs`, `csVerb(id, verb, note?) → cs` (verb ∈ validate|preview|approve|reject|apply|revert), `file(path) → {path, text, parsed} | null` (404 → null), `setPreview(id|null)`, `previewId()`; while a preview id is set, `meta`, `list`, `get`, `dashboard` call `/api/v1/preview/{id}/…` and every write rejects with `ApiError(405, "preview_read_only")` without a request. `api.meta()` fills `m.changesets` with `{propose:false, approve:false, approve_high:false}` when absent.
`api.runChange({title, reason, ops}, {canApprove, canApproveHigh}) → {cs, applied: bool}`: propose → validate → preview; if `cs.risk === "low"` and `canApprove` (or medium/high are never auto) → approve → apply; stops and returns the change set at the first `invalid`. Rejects with the ApiError of a failing step.

### Task 5: `ubah.js` op builders (pure)

**Files:** Create `web/app/ubah.js` (pure part above the `browser only` line, same pattern as `dashboard.js`), `web/app/test/ubah.test.js`; add `<script src="ubah.js">` to `index.html` before `dashboard.js`.

**Interfaces — Produces on `RangkaApp` (`RA`)** — each returns `{title, ops}` (title in Bahasa Indonesia); `existing` is the `api.file()` result for the target path (`null` when absent). New files are a `create` op with the header line and the one required key, followed by a `patch` op on the same path for the rest (so the kernel writes clean YAML):
- `RA.opsDashboard(def, widgets, existing)` → `dashboards/<def.name>.rk`; `widgets` = full ordered list with `span`.
- `RA.opsFormLayout(model, layout, existing)`, `RA.opsListColumns(model, columns, existing)`, `RA.opsKanbanColumns(model, values, existing)` → `custom/<model>.rk` `views.*`.
- `RA.opsMenu(layoutName, side, existing)` → `layouts/<layoutName>.rk` `/nav/side` (when `existing` is null also a `config.rk` patch `replace /layout` only if config's layout differs).
- `RA.opsAddField(model, {label, type, options?}, existing)` → field name `x_` + slug of label (`slugField("Nomor PO") === "x_nomor_po"`), `views.form.add` and `views.list.add`.
- `RA.opsAddStatus(model, field, {value, label}, existing)`, `RA.opsAddApproval(model, {on, when, approvers, label}, existing)`.
- `RA.opsAddAutomation(app, model, {name, label, when, set|notify})` → `apps/<app>/flows/<name>.rk` (`modules/` when the model's module is a module), `on: <model>.updated`, an `if:` and one `update`/`notify` step.
- `RA.opsAddModel(app, {label, fields:[{label,type}]}, layoutName, layoutExisting)` → `apps/<app>/models/<name>.rk` (fields, `views.list.columns`, `views.form.layout`, `permissions` copied from a sibling model is NOT done: the model gets no `permissions` block) + menu entry `{to: "model:<name>"}` in the layout's `nav.side` (a group "Tabel baru" when no group fits).
- `RA.moveItem(list, from, to)`, `RA.slugField(label)`, `RA.slugName(label)`.

### Task 6: Ubah UI in the app

**Files:** `web/app/ubah.js` (browser part), `web/app/shell.js`, `web/app/dashboard.js`, `web/app/form.js`, `web/app/list.js`, `web/app/index.html` (CSS `ap-ubah-*`, incl. ≤ 600px rules), tests in `web/app/test/ubah.test.js` and `shell.test.js` for pure helpers.

**Interfaces:** `RA.UbahCtx` React context `{on, canPropose, preview, run(change) → Promise, toggle()}` provided by the shell; `ctx.reloadMeta()` (shell) re-fetches meta after apply/undo/preview change.

Behaviour (UI copy fixed here):
- Top bar Segmented "Pakai" / "Ubah" (`aria-label="Mode"`) only when `meta.changesets.propose`; `?ubah=1` starts in Ubah. Ubah shows a thin Bata bar "Mode ubah · perubahan jadi change set".
- After a low-risk apply: toast "Perubahan diterapkan" with action "Urungkan" (revert → reload meta → toast "Perubahan dibatalkan").
- Medium/high or not approver: a card (`role="dialog"`, title "Perlu persetujuan") with risk badge ("Risiko sedang"/"Risiko tinggi"), the reasons from the change set's last `proposed` history note, the dry run (`preview.migrations` as code lines, `preview.files` paths, `preview.affected` counts), buttons "Pratinjau" (sets preview, banner), "Setujui & terapkan" (only when `approve` and, for high, `approve_high`; then apply, toast with "Urungkan"), "Tolak", "Tutup". Invalid → the card shows "Belum valid" and the validation messages.
- Preview banner: "Pratinjau: <title>" + "Keluar pratinjau"; write buttons hidden (shell passes `readOnly`).
- Dashboard in Ubah: each widget card draggable (HTML5 DnD, `data-widget=<name>`), plus per-widget buttons "Geser kiri", "Geser kanan", "Lebar −", "Lebar +" (span 1–12) for keyboard/touch; any change runs `opsDashboard`.
- Form in Ubah: field rows draggable with "Naik"/"Turun"; "Tambah kolom isian" dialog (label, type: Teks/Angka/Tanggal/Pilihan/Ya-tidak, options for Pilihan); "Tambah persetujuan" dialog (saat: Kirim/Batal, syarat CEL optional, penyetuju: role select); "Tambah otomasi" dialog (saat field berubah menjadi nilai → isi field lain).
- List in Ubah: column chips with "←"/"→" and "Sembunyikan"; kanban columns with "←"/"→" and "Tambah tahap" (opsAddStatus).
- Sidebar in Ubah: items with "Naik"/"Turun"/"Sembunyikan", group rename inline, "Tambah tabel" dialog (nama tabel, up to 5 kolom). Sidebar renders from `meta.layout.nav.side` when present (else app menus, unchanged).
