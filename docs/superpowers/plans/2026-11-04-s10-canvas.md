# S10 Process Canvas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One canvas per business process, built from `.rk` metadata, whose stages expand in place and whose node edits become change-set ops, embeddable by the Console, the web app and Rangka Cloud (S12).

**Architecture:** A new kind `process` (`processes/<name>.rk` in a module, app or site; contract 0014) names a process and its stages. A new kernel package `internal/canvas` turns a process plus the registry into a graph (groups = stages; nodes = triggers, conditions, rules, actions, approvals, lifecycle steps; edges), every node carrying its `.rk` file, JSON pointer, line and column. Edits are turned into change-set ops by splicing the new scalar into the original text (byte-preserving) or, when that is impossible, a JSON-Patch op. The API serves graphs permission-filtered and stores layout only in `<site>/canvas/<process>.json`. `web/canvas/` is a React 18 UMD component with no build step.

**Tech Stack:** Go 1.24 kernel, strict YAML `.rk` (`internal/rk`), JSON Schema 2020-12 (`schema/0.5`), Python reference validator (`tools/rangka_validate.py`), React 18 UMD + Rangka design system (`web/design-system/bundle.js`), Playwright (Python).

**Spec:** `docs/superpowers/specs/2026-11-03-first-pilots-design.md` (Decided → Process canvas, option A expand in place); program plan `docs/superpowers/plans/2026-11-03-pilot-program.md` (S10, Fixed interfaces, Global Constraints).

## Fixed interfaces (S12 builds against these)

`GET /api/v1/processes` → `{data: [{name, label, inferred, stages, source}]}` (only processes with at least one stage the caller may read).

`GET /api/v1/processes/{name}` →
```json
{"name": "lead_to_cash", "label": {"id": "Dari lead sampai lunas"}, "inferred": false,
 "source": {"file": "apps/crm/processes/lead_to_cash.rk"},
 "groups": [{"id": "lead_in", "label": {"id": "Lead masuk"}, "model": "lead", "models": ["lead"], "when": "",
             "source": {"file": "…", "path": "/stages/0", "line": 5, "col": 5},
             "nodes": ["<node id>", "…"], "counts": {"trigger": 1, "rule": 1, "action": 1, "approval": 0, "step": 4, "condition": 1}}],
 "nodes": [{"id": "modules/pipeline/models/deal.rk#/automations/0", "group": "deal", "kind": "trigger|condition|rule|action|approval|step",
            "label": {"id": "…"}, "detail": "stage changes to 'won'", "model": "deal",
            "source": {"file": "modules/pipeline/models/deal.rk", "path": "/automations/0", "line": 120, "col": 5},
            "editable": {"when": "stage changes to 'won'", "if": "app_installed('invoicing')"}}],
 "edges": [{"from": "<id>", "to": "<id>", "kind": "flow|lifecycle|handoff", "label": {"id": "…"}}],
 "layout": null}
```
Node id = `<file>#<JSON pointer>` (a guard condition: the guarded item's pointer + `/if` or `/when`; a lifecycle step: the option's pointer, e.g. `…/fields/3/options/4`; a derived-status step: `<model file>#status/<value>`; a stage-level `when` step: `<process file>#/stages/<i>/when`). `editable` maps key paths (dot-separated, relative to the node's `source.path`, e.g. `when`, `message.id`, `set.status`, `approvers`) to current values.

`POST /api/v1/processes/{name}/ops` `{edits: [{node, key, value}]}` → `{title, ops}` (compute only; 400 `bad_edit` for an unknown node/key; empty `ops` when every value equals the current one). The client then `POST /api/v1/changesets {title, ops}`.

`PUT /api/v1/processes/{name}/layout` `{groups: {<id>: {collapsed?: bool, x?: number, y?: number}}, nodes: {<id>: {x, y}}}` → 200 layout; writes `<site>/canvas/<name>.json` (2-space JSON, sorted keys, trailing newline). Owner (or system) only, 403 `permission_denied` otherwise; 400 `bad_layout` for other keys.

Web: `window.RangkaCanvas = {Canvas, mount(el, opts), client(baseUrl)}` from `web/canvas/canvas.js` + `web/canvas/canvas.css`.

## Rulings (made while planning; check these)

1. **Declared, then inferred.** Inference alone cannot name "Lead masuk"/"Lunas" or say that two stages share `sales_invoice`, so contract 0014 adds kind `process`. Every installed app (kind app or legacy) with a `menu:` and no declared process of the same name also gets an inferred process `<app>` (one stage per non-child menu model, menu order), so any bundle has a canvas without authoring.
2. **Stage keys:** `{name, label, model, when?, models?}`; `when` is a CEL condition on the stage model (`status == 'paid'`); `models` adds models whose nodes join the stage; models that are not installed are skipped silently (a process may span optional modules).
3. **Byte-stable edits:** a scalar edit splices the re-quoted scalar into the original text at its exact span (comments and formatting kept) and emits op `replace` with the full new text; non-scalar or multi-line targets fall back to op `patch` (JSON Patch, re-dumped by `rk.Dump`).
4. **Permissions:** a stage (and its nodes) shows only when the caller has model-level `read` on its model (`Engine.Allowed(a, model)["read"]`); nodes of `models:` entries likewise; a flow joins a stage when a step creates/updates/finds the stage model. A process with no visible stage is 404 `not_found` (no leak of its existence).
5. **Layout is not metadata:** stored directly by `PUT …/layout` (owner only), never through a change set; it never changes behaviour.
6. **rangka-apps process files** (`apps/crm/processes/lead_to_cash.rk`, `apps/jasa_proyek/processes/quote_to_cash.rk`) are proposed in the contract; the kernel tests use a snapshot under `kernel/testdata/canvas/`. Adding them to rangka-apps is a follow-up PR there.

## Review Focus

- **A rule, approval or field added by a company overlay (`custom/<model>.rk`)**: its node's source is the overlay file and pointer, not the app file (Task 2 test `TestOverlayNodeSource`).
- **An edit whose value needs quoting** (`'won'`, a value with `: ` or `#`, a value inside a flow map `{id: …}`): the spliced file parses to the new value and every other byte is unchanged (Task 2 `TestSpliceQuoting`).
- **A sales_rep viewing a process whose middle stage they cannot read**: that stage disappears, the handoff edge joins its neighbours, no node of the hidden model leaks (Task 3 `TestProcessPermissionFilter`).
- **A layout file that is missing, empty or broken JSON**: the graph still renders with `layout: null` (Task 3 `TestLayoutBroken`).
- **A long process on a 400 px screen**: the canvas scrolls horizontally inside its own container, the page never does (Task 4 Playwright at 400 px).

- Produces:
  - `canvas.Processes(reg *meta.Registry) []*meta.Process` — declared + inferred (ruling 1), sorted by name; inferred have `File == ""` and `App` set.
  - `canvas.Build(reg *meta.Registry, p *meta.Process, canRead func(model string) bool) *Graph` — `Graph{Name string; Label meta.Label; Inferred bool; Source Source; Groups []Group; Nodes []Node; Edges []Edge; Layout any}` with JSON tags exactly as in Fixed interfaces; `Source{File, Path string; Line, Col int}` (`omitempty` on path/line/col).
  - `canvas.Ops(reg *meta.Registry, g *Graph, edits []Edit) (title string, ops []changeset.Op, err error)`; `Edit{Node, Key string; Value any}`; error `*canvas.EditError{Code: "bad_edit", Msg}`.
  - `canvas.Splice(doc *rk.Doc, pointer string, value any) (text string, ok bool)` — ok=false when the target is not a single-line scalar.

Node rules (per visible stage model, in this order, ids per Fixed interfaces):
- **trigger:** each `automations[i]` (`detail` = its `when`, editable `when`, `do`); each flow whose steps `create`/`update`/`find`/`find_all` the stage model (`detail` = `on` or `schedule`; node per flow, source `/`), its steps become `action` nodes (`detail` = the step verb + target, editable = the step's scalar keys incl. `set.<field>`), edges `flow` in step order.
- **condition:** an `if` on an automation, action, flow or flow step → condition node before the guarded node (editable `if`); a stage `when` → step node (below).
- **rule:** `rules[i]` (`detail` = `check`, label = `message`, editable `check`, `message.id`, `level`).
- **action:** `actions[i]` (label, `detail` = hook, editable `label.id`, `if`); `on_submit`/`on_cancel` hooks as action nodes (pointer `/on_submit/<i>`).
- **approval:** `approvals[i]` (label, `detail` = `on` + `when`, editable `when`, `approvers`, `label.id`).
- **step (lifecycle):** the model's lifecycle field = kanban `group_by`, else select field `status`, else `stage`; one node per option in order, `lifecycle` edges between consecutive options. A submittable model without such a field gets derived steps `draft → submitted → partly → paid`, plus `overdue` and `cancelled` (labels Draf, Diajukan, Dibayar sebagian, Lunas, Jatuh tempo, Dibatalkan as in `web/app/list.js` STATUSES). A stage with `when` gets one step node (pointer `/stages/<i>/when`, editable `when`) and claims that derived/option step from earlier stages of the same model (the step moves to it).
- **handoff edges:** from the last lifecycle step (else last node) of stage i to the first node of stage i+1; `label` = the link field joining the two models (either direction, e.g. `lead.converted_deal`, `sales_invoice.customer_order`), else none. Hidden stages are skipped so neighbours join.
