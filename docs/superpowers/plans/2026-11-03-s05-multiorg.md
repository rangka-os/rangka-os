# S5 Multi-org and Row Scope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One user belongs to several orgs and switches between them; outlet staff see only their outlets'
records in lists, dashboards, single-record calls, MCP and SSE; Postgres RLS backs the org boundary.

**Architecture:** Org isolation already exists in SQL (`org_id` on every table and query). This stream adds
membership listing and switching in `auth`/`api`, per-org settings in `meta`, an org GUC set per pooled
connection from the request context plus RLS policies in `store` DDL, and a role `scope` evaluated in
`engine` at its public entry points and in the realtime hub.

**Tech Stack:** Go 1.24 kernel (in-tree `pg` client), PostgreSQL 16, JSON Schema 2020-12, Python reference
validator (`tools/rangka_validate.py`).

**Spec:** `docs/contracts/0010-multi-org-and-row-scope.md` (this branch); program plan
`docs/superpowers/plans/2026-11-03-pilot-program.md` stream S5.

## Review Focus

- **Removed membership with a live session or token:** next request is 401, not silently moved to the default org. Test in Task 3.
- **Outlet user creates or re-points a record to another outlet:** 403 `permission_denied`, nothing written. Test in Task 6.
- **Dashboard cache shared between an owner and an outlet user of the same org:** each sees its own totals. Test in Task 6.
- **Scoped member with no outlets assigned:** sees no scoped records (fail closed), unscoped models still visible. Test in Task 6.
- **Kernel connected as a superuser (RLS bypassed):** startup logs a warning; the RLS test connects as a plain role so it really exercises the policy. Test in Task 5.
