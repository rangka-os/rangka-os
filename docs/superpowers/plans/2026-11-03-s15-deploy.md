# S15 Hosting on juragan.ai Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `deploy/juragan/`: one VM runs both pilots (Docker Compose: release image, one Postgres with a database per pilot, Caddy TLS), backs them up nightly to off-box object storage, and a restore drill proves a backup recovers on another machine.

**Architecture:** One Compose project. `postgres` (16) holds databases `jasa` and `fnb`, each with its own role. Two kernel services `jasa` and `fnb` run the same image, each with its own `/srv` project folder (apps/, site/, data/) and `DATABASE_URL`; the kernel migrates on start. `caddy` terminates TLS for `${JASA_HOST}` and `${FNB_HOST}`. A `backup` image (postgres:16 client tools + rclone + age + the rangka binary) is run nightly by a systemd timer; it uses `rangka backup` when the binary has it (S1) and falls back to `pg_dump` otherwise, writes an age-encrypted archive with a manifest (per-table counts and checksums), and uploads it with rclone. `restore-drill.sh` fetches the newest archive, restores it into a throwaway Compose project, boots the kernel on it and compares the manifest.

**Tech Stack:** Docker Compose v2, PostgreSQL 16, Caddy 2, rclone (S3 API), age, bash, systemd timers.

**Spec:** `docs/superpowers/specs/2026-11-03-first-pilots-design.md` (Answers §3, stream 15), program plan `docs/superpowers/plans/2026-11-03-pilot-program.md` (S15, go-live gate), contract `docs/contracts/0005-pilot-readiness.md` §2.

## Global Constraints

- Secrets only via `${ENV}` from `deploy/juragan/.env` (never committed; `.env.example` lists every key with empty or placeholder values). Compose uses `${VAR:?}` for required secrets so a missing one stops `up`.
- One database per pilot; the `jasa` role cannot connect to `fnb` and vice versa.
- Hostnames `jasa.juragan.ai`, `fnb.juragan.ai` are placeholders set by `JASA_HOST`, `FNB_HOST`.
- Release image `ghcr.io/rangka-os/rangka:${RANGKA_TAG}` (distroless, nonroot uid 65532, no shell); pinned tag, never `latest`.
- Backup CLI (S1, contract 0005 §2): `rangka backup [--out file]`, `rangka restore <file>`. Scripts detect it with `rangka help 2>&1 | grep -q 'rangka backup'` and fall back to `pg_dump -Fc` / `pg_restore`.
- Kernel facts used: `rangka serve` migrates on start; `rangka seed` creates the owner from `RANGKA_OWNER_EMAIL`/`RANGKA_OWNER_PASSWORD`; org id from `RANGKA_ORG`; files storage `system.rk` `files.path: ./data/files` → `/srv/data/files`; unauthenticated liveness `GET /.well-known/openid-configuration`; `POST /auth/login {email,password}`.
- No real customer data anywhere in this repo; local tests use `rangka-apps/sites/kopi-senja`.
- Creating cloud resources, DNS, money, credentials: runbook steps for Dede only.
- Shell scripts: `#!/usr/bin/env bash`, `set -euo pipefail`, pass `shellcheck`.

## Review Focus

- **Off-box upload fails** (bucket down, bad key): backup exits non-zero, keeps the local archive, the systemd unit is marked failed, no success ping. Test in Task 2.
- **Corrupted or truncated archive:** the drill fails at the checksum step, before touching a database. Test in Task 3.
- **Restore into a database that already has tables:** refused, with no override flag; the drill always uses a fresh project. Test in Task 3.
- **Missing secret in `.env`:** `docker compose config` fails naming the variable. Test in Task 1.
- **Cross-pilot access at the database:** the `jasa` role is refused on database `fnb`. Test in Task 1.

### Task 2: Nightly backup to off-box storage

**Files:** create `backup/Dockerfile`, `backup/lib.sh`, `backup/backup.sh`, `systemd/juragan-backup.service`, `systemd/juragan-backup.timer`; modify `compose.yaml` (service `backup`, profile `tools`), `.env.example`, `local/compose.local.yaml` (MinIO `offbox` + bucket init), `local/e2e.sh` (section "backup").

**Interfaces — Produces:**
- `backup.sh <jasa|fnb|all>` → for each pilot writes `/backups/<pilot>/<pilot>-<YYYYmmddTHHMMSSZ>.tar.age` and uploads it to `offbox:${BACKUP_BUCKET}/<pilot>/`; exits non-zero on any failure; pings `${BACKUP_PING_URL}` (optional) only on success; keeps local archives `BACKUP_KEEP_LOCAL` days (default 7). Never deletes remote objects (retention is the bucket's lifecycle rule; the backup key has no delete right).
- Archive (before age): tar with `manifest.json`, `db.dump` (pg_dump -Fc) **or** `rangka.backup` (S1), `site.tar` (`/srv/site`), `files.tar` (`/srv/data`), `SHA256SUMS` over the other members.
- `manifest.json`: `{pilot, created_at, method: "pg_dump"|"rangka", rangka_version, postgres_version, tables: {"<schema>.<table>": {rows, md5}}}`. Counts/md5 are taken in the same `REPEATABLE READ` snapshot as `pg_dump --snapshot` (bash `coproc psql`, `pg_export_snapshot()`); in the `rangka` method counts are taken before and after and the backup is retried once if they differ.
- `lib.sh`: `table_stats <db_url>` prints `schema.table<TAB>rows<TAB>md5` sorted (md5 of `string_agg(t::text, E'\n' ORDER BY t::text)`, via `query_to_xml` so it is one statement); `has_rangka_backup` returns 0 when the binary supports it.
- Env: `BACKUP_BUCKET`, `BACKUP_AGE_RECIPIENT` (required; `BACKUP_ALLOW_PLAINTEXT=1` only for local debugging, then the suffix is `.tar`), `RCLONE_CONFIG_OFFBOX_TYPE=s3`, `RCLONE_CONFIG_OFFBOX_PROVIDER`, `RCLONE_CONFIG_OFFBOX_REGION`, `RCLONE_CONFIG_OFFBOX_ENDPOINT` (blank for AWS), `RCLONE_CONFIG_OFFBOX_ACCESS_KEY_ID`, `RCLONE_CONFIG_OFFBOX_SECRET_ACCESS_KEY`, `BACKUP_PING_URL`.
- systemd: `ExecStart=/usr/bin/docker compose -f /opt/juragan/deploy/juragan/compose.yaml --env-file /opt/juragan/deploy/juragan/.env run --rm backup all`, timer `OnCalendar=*-*-* 02:00:00 Asia/Jakarta`, `Persistent=true`, `RandomizedDelaySec=10m`.

Then stop `offbox`, run backup again: exit status non-zero, a new local archive exists, the MinIO listing is unchanged after restart.

### Task 3: Restore and the restore drill

**Files:** create `backup/restore.sh`, `restore-drill.sh`; modify `local/e2e.sh` (section "drill").

**Interfaces — Consumes:** Task 2's archive layout and `table_stats`.
**Produces:**
- `restore.sh <archive> <pilot>` (in the backup image; `DATABASE_URL` and `/srv` of the target pilot mounted): decrypt with `/run/secrets/age-identity` (or `AGE_IDENTITY_FILE`), verify `SHA256SUMS` first, refuse when the target database has any table in schema `public` or `rk*`, restore (`rangka restore` or `pg_restore --no-owner --role=<pilot> --exit-on-error`), unpack `site.tar`/`files.tar` into `/srv`, then compare `table_stats` with the manifest; print `restore ok: <n> tables, <rows> rows match` or list each mismatching table and exit 1.
- `restore-drill.sh [--pilot jasa|fnb|all] [--archive file] [--identity file] [--env file]`: on any machine with Docker; downloads the newest archive per pilot with rclone (or takes `--archive`), starts project `juragan-drill-<epoch>` (postgres + the pilot's kernel, no Caddy, a random localhost port), runs `restore.sh`, starts the kernel, checks `/.well-known/openid-configuration` 200 and that `rangka migrate --dry-run` reports `0 statement(s)` (schema matches the binary), prints `DRILL PASSED <pilot> <archive> <UTC time>` and appends it to `drill.log`, tears the project down unless `--keep`.
