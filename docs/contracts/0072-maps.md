# 0072 Maps: tiles, geocoding, offline and privacy

Status: proposed (20 Nov 2026; `system.rk` `maps`, both validators and the app's `img-src` are implemented with this
contract) · Owner of the change: rangka-os (schema, validators, kernel, web app) · Affects: rangka-cloud (private: its
tile source, §2.3), rangka-apps (map views and widgets, #251 to #253), rangka-ai (Raka writes `maps` only on request,
#255) · Builds on 0017 §2 (platform egress), 0040 (what the host sets) · Issues: rangka-os#247 (this), parent #246;
cited by #248, #250 to #255

Number: claimed when the PR opened (0072 was the next free number on `main`).

## Context

- A map needs two outside services. **Tiles**: the images (or vector data) the browser draws. **Geocoding**: an
  address to a point, and a point back to an address.
- The free defaults have usage policies a multi-tenant SaaS can break:
  - OSM standard tiles (`tile.openstreetmap.org`) forbid heavy use, bulk or offline prefetch, and requests without a
    proper Referer or User-Agent. Attribution is required.
  - Public Nominatim allows at most 1 request per second per application, has no autocomplete, wants results cached,
    and wants a User-Agent that names the application.
- Today the kernel stores a point as a `geo` field (`{lat, lng}`, contract 0030) and the app links out to Google Maps
  (`web/app/media.js` `mapsUrl`). There is no map view, no geocoder and no `maps` setting.
- The web app has no Content-Security-Policy on its pages; any host can serve an `<img>` there.

## Decision

### 1. Library

- **Leaflet 1.9.4** (BSD-2), vendored in `web/app/vendor/`, with **Leaflet.markercluster 1.5.3** (MIT). Vector tiles
  (§2.2 `kind: vector`) are drawn by **protomaps-leaflet** (BSD-3), vendored the same way. #248 does the vendoring.
- No Google Maps or Mapbox SDK, and no API key anywhere in the browser.

### 2. Tiles: one setting

`system.rk`:

```yaml
maps:
  enabled: true                 # default; false = no map views, no /geo endpoints, no tile origin in img-src
  tiles:
    url: https://tile.openstreetmap.org/{z}/{x}/{y}.png   # default
    attribution: © OpenStreetMap contributors             # default
    max_zoom: 19                # 1..22, default 19
    subdomains: [a, b, c]       # optional; only with {s} in url
    kind: raster                # raster (default) | vector
    cache_tiles: 300            # 0..300, default 300 (§4)
```

1. **Validation** (`schema/0.5/system.json`, both validators):
   - `url` is `https://`, a host (optionally `{s}`-prefixed, optionally a port), and a path with `{z}`, then `{x}` and
     `{y}` in either order. No `${VAR}`: every browser reads this URL, so it is public. Never put a secret key in it.
   - `tiles` given means `url` and `attribution` are both required: another source has its own terms, so OSM's
     attribution is never the silent default for it.
   - `maps_subdomains` (error): `{s}` in `url` without `subdomains`, or `subdomains` without `{s}`.
2. **Defaults.** No `maps` block, or no `tiles`, means OSM standard tiles. That fits `rangka dev`, a self-hosted kernel
   and a small tenant. A kernel never prefetches OSM tiles (§4), and the browser sends its own Referer.
3. **Rangka Cloud sets its own source**, as configuration only. The kernel ships no AWS code and no tile server.
   - **(a)** self-hosted raster tiles: `kind: raster`, `url` at the mirror.
   - **(b)** a Protomaps extract of Indonesia (PMTiles on S3 + CloudFront, served as `{z}/{x}/{y}.mvt`), drawn by
     protomaps-leaflet: `kind: vector`. No policy limits; storage and egress only; one extract job a month.
   - **Recommendation: (b) for Cloud, OSM for self-host.** The choice and its cost are Rangka Cloud's (Dede). Until
     Cloud sets `maps.tiles`, Cloud tenants use the OSM default, which is fine at pilot volume.
4. The kernel reads the setting through `internal/maps` (`maps.FromSystem(reg.SystemConfig("maps"))`), which fills
   the defaults. The map component (#248) gets it from the meta the app already loads: `GET /api/v1/meta` carries
   `maps: {enabled, tiles: {url, attribution, max_zoom, subdomains, kind, cache_tiles}, geocoder: {enabled}}` with the
   defaults filled in (`site.system` redacts every `url`, so it is not the source). Nothing else of the geocoder
   reaches the browser.

### 3. Geocoding: a kernel proxy

```yaml
maps:
  geocoder:
    enabled: true               # default
    provider: nominatim         # nominatim (default) | photon
    url: https://nominatim.openstreetmap.org   # default for nominatim; https://photon.komoot.io for photon
    rate_per_second: 1          # > 0, max 50, default 1
    cache_days: 30              # 1..365, default 30
    contact: ops@example.id     # optional; goes in the User-Agent
    countries: [id]             # ISO 3166-1 alpha-2, lower case; default [id]; [] = no limit
```

1. The browser never calls the provider. The kernel serves `GET /api/v1/geo/search?q=` and
   `GET /api/v1/geo/reverse?lat=&lng=` (#254), signed-in members only.
2. **Rate.** One token bucket per kernel process at `rate_per_second`. A request over the rate waits briefly, then
   answers 429 `geo_busy`. `maps_rate_limit` (error, both validators): `rate_per_second` above 1 while the URL is public
   Nominatim (`nominatim.openstreetmap.org`). A self-hosted Nominatim may go faster.
3. **Cache.** Answers are kept `cache_days` (key: provider, normalised query or rounded point, countries), shared by all
   members of the installation. A cached answer costs no request.
4. **User-Agent.** `Rangka/<version> (+<auth.issuer>; <contact>)` (`maps.Settings.UserAgent`), so the provider can
   tell installations apart and reach the operator.
5. **Default: public Nominatim**, with Photon (komoot's public instance or self-hosted) as configuration only. Photon
   offers autocomplete, but its public instance is fair-use without a stated limit; Nominatim's policy is explicit,
   which is easier to stay inside. Search is on submit, not per keystroke.

### 4. Offline

- The service worker never prefetches tiles, for any source.
- Tiles the person has already seen may stay in a runtime cache of at most `cache_tiles` entries (least recently used
  out), so the last viewed area still draws on a weak signal. `cache_tiles: 0` keeps none.
- Geocoding needs the network. Offline, the search box says so; a point picked on the map still saves (0030 `geo`).

### 5. Privacy

- The tile host receives only tile coordinates `z/x/y` (which area is on screen), never a record, a name or a field.
  The browser sends the person's IP to the tile host; this is unavoidable for any tile source the browser loads, and
  is why Cloud's own source (§2.3) is recommended.
- Geocoding queries go through the kernel, so the provider sees the kernel's address and the query text, never the
  person's IP or session. Do not geocode customer addresses in bulk through a public provider.
- Coordinates in records follow the field's own permissions (`hidden_for`, contract 0030); a map view shows only the
  records a person can already read (#251).

### 6. CSP and egress

1. **`img-src` (implemented).** Every page of the end-user app (`/app/` and its `.html` files) carries
   `Content-Security-Policy: img-src 'self' data: blob: <tile origins>`. The tile origins come from `maps.tiles.url`,
   one per subdomain when the URL has `{s}`; with maps off, none. Only plain `https://host[:port]` origins are written;
   anything else is left out of the header. So no host other than the kernel and the tile source can serve an image
   in the app (no tracking pixel, no hotlinked logo). Other directives stay unset until their own contract.
   - `kind: vector` loads tiles with `fetch`, so #248 adds the same origins to `connect-src` when it sets one.
   - The console (`/console/`) and the portal (`/portal/`) keep their own headers.
2. **Egress.** The geocoding proxy dials only `maps.Settings.GeocoderHost()`: the host of `maps.geocoder.url`, https
   only, empty when the geocoder is off. It dials through the connector egress policy (`RANGKA_CONNECTOR_EGRESS`,
   contract 0017 §2), so a geocoder URL that resolves to a private address is refused unless the platform allows it.

## What stays out

- Routing and directions, travel time, and live tracking.
- Drawing areas (polygons) and storing shapes; a `geo` field stays a point.
- Any paid tile or geocoding API, and any key in the browser.
- Bulk geocoding of imports (a later issue, with a self-hosted geocoder).
