# S3b Print tax figures and validator parity: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Pilot invoices print the PPN rate and the DPP factor from configuration, never a hard-coded 12%. Per-org config overrides deep-merge with the site config. The Python reference validator checks the `print` and `letterhead` kinds, so compare-python covers them.

**Spec:** `docs/contracts/0008-print-formats.md`, `docs/contracts/0010-multi-org-and-row-scope.md` §2 (org overrides). The integrator's rulings of 4 Nov on the PR #14 follow-ups are binding: tax labels come from config; `OrgConfig` deep-merges, so an org-level `tax` without `pkp` keeps the base `pkp`; print also needing `read` stays.

## Global Constraints
- Branch `pilot/s03b-print-tax`. Stdlib only, gofmt, and English code. Document text in Bahasa Indonesia.
- No hard-coded tax rate or DPP factor in any `templates/print/*.html`.
- Keep `make -C kernel vet test compare-python` green; compare-python must stay byte-identical.
- No real customer data.

## Review Focus
- **A submitted invoice whose rate differed from today's config** (an invoice made at 11% after config moved to 12%): the label prints the record's own rate. Test in Task 2.
- **An org override with `tax: {ppn_rate: 11}` only:** `pkp` and `dpp_ratio` come from the site. Test in Task 1.
- **An override value that is a list or a scalar where the site has a map, or the reverse:** the override replaces the value and nothing panics. Test in Task 1.

### Task 1: Deep-merge per-org config (meta)
**Files:** `kernel/internal/meta/orgs.go`, `kernel/internal/meta/orgs_test.go` (create or extend).
**Produces:** `(*Registry).OrgConfig(org, path string) any`, same signature. When both the org's value and the site's value at a key are maps, merge them recursively and let the org win. Any other type pair: the org value replaces the site value. Never mutate the site or org maps; return copies of merged maps.
- [ ] Failing tests:
  - Site `tax: {ppn_rate: 12, dpp_ratio: "11/12", pkp: true}` with org `bebas` `config: {tax: {ppn_rate: 11}}` gives `OrgConfig("bebas","tax.pkp") == true`, `OrgConfig("bebas","tax.ppn_rate") == 11` and `OrgConfig("bebas","tax.dpp_ratio") == "11/12"`.
  - `OrgConfig("bebas","tax")` is a merged map. Mutating it leaves the site config unchanged.
  - An org scalar over a site map, and an org map over a site scalar, both give the org value.
  - Unknown org gives the site value. An org without that key gives the site value.
- [ ] Implement, then run `go test ./internal/meta/`, then the full `make -C kernel test`. Other streams' tests that relied on replace semantics must still pass. If any fails, report it and do not change it silently.
- [ ] Update the print test that pinned the old replace semantics (`TestPrintOrg` "bebas" in `kernel/internal/api/print_test.go`) to the new rule. Update contract 0010 §2 wording ("deep-merged") and the print guide's "Organisation data" note.
- [ ] Commit `meta: deep-merge per-org config overrides (contract 0010)`.

### Task 2: Tax labels from config and from the record (docprint, api, layouts)
**Files:** `kernel/internal/api/print.go` (Input), `kernel/internal/docprint/render.go` (data key), `templates/print/{quotation,sales_invoice,purchase_order}.html` plus the fixture copies, goldens, `templates/print/README.md`, contract 0008 §3.
**Produces:** template data key `.Tax`, a map with `ppn_rate` (number, default 12), `dpp_ratio` (string, default `"11/12"`) and `pkp` (bool). It is built in the endpoint from `OrgConfig(org,"tax")` with those defaults. `docprint.Input` gains `Tax map[string]any`.
- Layout rule (the same in every layout):
  - Rate shown = the record's own `ppn_rate`, else its `tax_rate` (non-empty), else `.Tax.ppn_rate`. Print it with `number` as `PPN 12%` or `PPN 11%`.
  - The DPP label is `DPP nilai lain ({{dpp_ratio}})` when the ratio is not `1` or `1/1`. Otherwise it is `DPP`.
  - Amounts stay the record's own `dpp` and `ppn`; the layout never computes tax.
  - Add the PPN rate label to the PO, which currently has none.
- [ ] Failing tests (docprint goldens plus unit tests):
  - With `.Tax` `{ppn_rate: 11, dpp_ratio: "1/1"}` the invoice shows `PPN 11%` and `DPP` with no `(11/12)`.
  - A record with `ppn_rate: 12` under config 11 shows `PPN 12%`.
  - No `.Tax` at all shows `PPN 12%` and `DPP nilai lain (11/12)`.
  - A test greps `templates/print/*.html` for the literals `12%` and `11/12` and fails if either appears.
- [ ] Server test: a site with `tax: {ppn_rate: 11, pkp: true}` prints `PPN 11%`.
- [ ] Regenerate goldens. The only diffs allowed are the label rows that reach the defaults. Commit `print: PPN rate and DPP factor from the record or config`.
