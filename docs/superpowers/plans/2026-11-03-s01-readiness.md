# S1 Pilot Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the kernel safe for real pilot data: real pgx and bcrypt, `rangka backup`/`rangka restore`, safe migrations with dry run, rollback and a destructive-step guard, and model `permissions:` enforced on every interface.

**Architecture:** `internal/pg` keeps its public API and runs on pgx/v5 underneath; `internal/auth` hashes with bcrypt and upgrades old PBKDF2 hashes at login. A new `internal/backup` package writes a tar.gz with per-table `COPY` data, checksums, the site, apps and files. `store.Plan` returns typed steps with risk, reverse SQL and a destructive flag, recorded in `rk_migrations`. Permissions are decided once in `engine` (`Authorize`) and every interface (REST, MCP, SSE, print, attachments, imports) calls it or goes through engine methods that do.

**Tech Stack:** Go 1.24, `github.com/jackc/pgx/v5`, `golang.org/x/crypto/bcrypt`, PostgreSQL 16, `archive/tar` + `compress/gzip`.

**Spec:** `docs/superpowers/specs/2026-11-03-first-pilots-design.md`, program plan `docs/superpowers/plans/2026-11-03-pilot-program.md` (stream S1), contract `docs/contracts/0005-pilot-readiness.md`.

## Rulings (decided here, not in the contract)

1. **One PR for S1.** The program plan's one-stream-one-branch rule wins over 0005 §1's "one PR per library"; each library is its own commit. Only pgx and bcrypt are swapped; chi, cel-go, River, jsonschema, yaml.v3 stay stand-ins (program plan: "other stand-ins may follow").
2. **Permission actions** are the schema keys: `read, create, write, delete, submit, cancel, amend, export, import, print, customize`. The contract's "update" is `write`.
3. **Who is allowed:** an actor is allowed an action on a model when (a) `Actor.System` is true (seed, flows, automations, queue workers acting for the kernel), or (b) the actor has role `owner`, or (c) the model has no `permissions:` list (unchanged behaviour for models not yet annotated), or (d) some entry whose `role` is one of the actor's roles has `<action>: true` and, when it has `if:`, the CEL evaluates to `true` on the record (errors count as false). Grants from several roles are a union.
4. **Record vs model checks:** with a record, `if:` is evaluated (stored record for read/write/delete/submit/cancel/amend/print; the new record after defaults for create). Without a record (list, SSE subscribe, meta), a conditional grant counts as "maybe": lists then drop rows whose `if:` is false, SSE checks each event's record.
5. **Single record denied → 403**, not 404 (Review Focus: "403 `permission_denied` everywhere"). List rows denied by `if:` are silently dropped and not counted in `total`.
6. **Mapping:** GET record/list/SSE → `read`; POST create → `create`; PATCH, `actions/{action}`, unknown lifecycle verbs → `write`; DELETE → `delete`; lifecycle `submit|cancel|amend` → same name; `GET /r/{m}/{n}/print` → `print`; `GET /r/{m}/{n}/attachments` → `read`, `POST` → `write`; `GET|DELETE /attachments/{id}` and `POST /imports/{import}` → S6/S7 call `engine.Authorize` (read/write, import). Child models use the parent's permissions. Dashboards: a widget over a model the caller cannot read returns the 403 body in place of its data.
7. **Tokens** (API, MCP, Omilo) carry the member's roles and get exactly the same checks as a person.
8. **Backup is native Go** (`COPY ... TO STDOUT` per table through pgx), not `pg_dump`, so the single binary needs no client tools. Restore builds the schema by migrating from the archived apps + site, adds archived columns the models no longer have, then `COPY ... FROM STDIN` in foreign-key order and resets sequences.
9. **Scheduled backups (`backup:` in `system.rk`) are deferred**; S15's nightly `rangka backup` job covers the pilots. Follow-up after go-live.
10. **Production mode** = env `RANGKA_ENV=production`. Then `rangka migrate`, `serve`'s start-up migrate and change-set applies take a backup to `RANGKA_BACKUP_DIR` (default `<site>/backups`) before applying any statement.
11. **Destructive steps:** retyping a column to a non-widening type, soft-deleting a column/table the model no longer has, and dropping a soft-deleted column/table older than 30 days. Without `--allow-destructive`, a plan containing a retype is refused as a whole (exit 1, nothing applied); removed columns/tables stay notes as today. Soft delete = rename to `_del_<YYYYMMDD>_<name>` (max 63 bytes).
12. **Export** has no endpoint yet; `engine.Authorize(..., "export", nil)` is the hook for whoever adds one.

## Review Focus

- **Restore into a database that already has tables:** refused before writing anything. Test in Task 6.
- **A corrupted or truncated archive, or one made by a newer kernel:** refused with a clear message, nothing written. Test in Task 6.
- **A migration statement that fails half-way:** nothing applied, no `rk_migrations` row. Test in Task 5.
- **Rollback over a step with no reverse (dropped soft-deleted column):** refused, nothing changed. Test in Task 5.
- **A token of a role with conditional `if:` grants asking for someone else's record through REST, MCP and SSE:** 403 / no event. Test in Task 4 (matrix).
