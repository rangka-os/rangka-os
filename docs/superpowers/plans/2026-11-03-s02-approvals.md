# S2 Document Approvals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Model `approvals:` policies and a flow `approve` step that hold submit / cancel / actions / flows until a listed role approves, bound to a SHA-256 snapshot of the record, exposed over REST, SSE and MCP.

**Architecture:** Metadata (schema, `meta` parsing, Go + Python validators, overlays) → storage (`rk_approvals`, `store/approvals.go`) → engine (`engine/approvals.go`: hold, void on edit, approve/reject running the verb as the requester inside one transaction; flow `approve` step) → interfaces (`api/approvals.go`, 202 on held verbs, SSE `approval`, MCP tools).

**Tech Stack:** Go 1.24 kernel (in-tree pg stand-in), PostgreSQL 16, JSON Schema 2020-12, Python 3 reference validator.

**Spec:** `docs/contracts/0007-document-approvals.md` (this branch) · program plan `docs/superpowers/plans/2026-11-03-pilot-program.md` stream S2 · design `docs/superpowers/specs/2026-11-03-first-pilots-design.md`.

## Review Focus

- **Editing a draft after its approval request** (amount, customer, lines, child rows): every pending request for it becomes `void`; approve answers 409 `approval_void`; submitting again creates a new pending request. Test: Task 3 `TestApprovalVoidedByEdit`.
- **A write that bypasses the engine** (direct SQL update of a held record): approve recomputes the snapshot, voids, 409. Test: Task 3 `TestApprovalSnapshotMismatch`.
- **The verb fails at approve time** (a submit rule now fails because linked data changed): approve returns the 422, the request stays `pending`, the record stays draft. Test: Task 3 `TestApproveRollsBackWhenVerbFails`.
- **Two matching policies** (manager > Rp 10.000.000 and owner-only > Rp 100.000.000): the verb waits for both; approving one leaves `docstatus` 0. Test: Task 3 `TestTwoPoliciesBothNeeded`.
- **An API token or an MCP agent calling approve:** 403 `human_required`, nothing changes. Test: Task 5 `TestApprovalsREST` and Task 6 `TestApprovalsMCP`.

- `when` → the existing expression check (`check_expr` / Go equivalent) at `approvals/<i>/when`
- overlays: the same `unknown_verb` and `when` checks against the merged model, with the overlay's path
- flow `approve` steps: schema only, plus `parens` on `<step>/approve/when`

```go
// Result gains: Held bool `json:"-"`; Approvals []store.Approval `json:"-"`
// ActionResult gains: Held bool `json:"held,omitempty"`; Approvals []store.Approval `json:"approvals,omitempty"`; Record store.Record `json:"record,omitempty"`

func (e *Engine) Reject(ctx context.Context, a Actor, id, reason string) (*Decision, error)
func (o *op) hold(m *meta.Model, rec store.Record, snapshot, verb string, args map[string]any) (pending []store.Approval, all []store.Approval, err error)
```
Behaviour (contract §2–§5):
- `hold`: for each policy in `ApprovalsFor(verb)` whose `when` is empty or truthy on `rec`: if an `approved` row exists for (org, model, name, verb, policy, snapshot) it is satisfied; else insert a row (`pending`, or `approved` with `decided_by = actor` when `CanDecide(actor, row)`), audit `approval.requested` (or `approval.approved`), Notify. Returns pending rows and all rows for the call.
- `submit`: after warnings/force handling and before naming, compute `Snapshot` from the record **as loaded** (before `prepare`), call `hold(…, "submit", {"force": force})`; any pending → return `&Result{Record, Held: true, Approvals: all}` with **no error** (the inserts commit). `cancel` does the same with verb `cancel`; `runAction` with the action name and `{"args": args}` (before queueing).
- `update` and `Delete`: `store.VoidApprovals(org, model, name, "")`; each voided row → audit `approval.void` + Notify.
- `Approve`: `GetApproval(forUpdate)`; errors in order: not human → 403 `human_required` "Persetujuan harus dilakukan oleh orang yang masuk lewat aplikasi"; not pending → 409 `not_pending`; not owner/approver → 403 `permission_denied` "Kamu tidak termasuk penyetuju <label>"; for a record approval recompute `Snapshot` of the stored record: differs → `VoidApprovals` incl. this one, then return 409 `approval_void` "Dokumen berubah setelah diajukan; ajukan ulang" **after committing the void** (run the void in its own `e.run`). Then `DecideApproval(approved)`, audit, Notify; if no other pending row remains for (model, name, verb) run the verb in the same tx through an `op` whose actor is rebuilt from `Requester` (`Human` true): `submit(name, force)`, `cancel`, or `runAction(action, args)`. A verb error rolls the whole tx back and is returned.
- `Reject`: same guards; reason empty → 400 `bad_request` "Alasan penolakan wajib diisi"; set `rejected` with reason, void the other pending rows of (model, name, verb), audit, Notify.
