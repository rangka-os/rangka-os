# S0: End-user web app on the kernel — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the in-memory prototype into `/app/`, the web app business users sign in to: lists, forms with child tables, lifecycle, kanban, dashboards, approval inbox, print, attachments, imports and an org switcher, all on `/api/v1`.

**Architecture:** `web/prototype/` moves to `web/app/` and stays a no-build React 18 UMD app on the design system (`window.Rangka`), split into focused files that hang off `window.RangkaApp`. A data adapter `api.js` is the only code that calls the kernel; it also detects which pilot endpoints (S2, S3, S5, S6, S7) exist so the UI hides what is not installed. `engine.js` stays as the CEL subset, now created from `/api/v1/meta`, and is used only for live form feedback; every save, submit, approval and number comes from the server. The kernel already serves `rangka-os/web` at `/`; it gains `/` → `/app/` and `/prototype/` → `/app/` redirects and a `rangka user add` command the tests (and pilot set-up) need.

**Tech Stack:** Go 1.24 kernel (net/http), PostgreSQL 16 (throwaway cluster via `kernel/scripts/pgtemp.sh`), React 18.3.1 UMD + `web/design-system/bundle.js`, plain ES5-style JS (no build), `node --test` for adapter/engine unit tests, Python 3 + Playwright (Chromium) for the live suite.

**Spec:** `docs/superpowers/specs/2026-11-03-first-pilots-design.md` (answers 1, 4, 6) and `docs/superpowers/plans/2026-11-03-pilot-program.md` (stream S0, Fixed interfaces). Workspace rules: `~/Documents/works/rangka/CLAUDE.md`.

## Global Constraints

- Branch `pilot/s00-webapp`, worktree `~/Documents/works/rangka/.worktrees/rangka-os-s00`; small commits; PR to `main`, not merged by this stream.
- Code, comments, docs in English; UI text Bahasa Indonesia first, sentence case, "kamu"; rupiah `Rp 1.250.000` (no decimals); dates `27 Okt 2026`.
- IDR amounts are integers (whole rupiah); never float arithmetic on money in the browser beyond the live preview, and what is sent is an integer.
- Money, stock and document numbers are never decided by the client or an LLM: the server's response replaces the client's preview every time.
- Submitted documents change only through cancel + amend (the UI shows no edit controls when `docstatus` ≠ 0).
- No real customer data in fixtures, tests or screenshots; tests use the public demo site `rangka-apps/sites/kopi-senja` and `fixtures/`.
- Design: Ink `#1C1917` primary buttons, deep Bata `#A33B23` links/selection on Kapur `#F6EDE6`, focus Bata Terang `#E0623F`, danger stays red — all through the design-system tokens, no new colours.
- Every kernel change keeps `make -C kernel test` and `make -C kernel compare-python` green.
- Do not edit files owned by other streams (approvals, print, numbering, multi-org, attachments, imports code in `kernel/internal/*`); S0 only consumes their endpoints.

## Rulings made for this stream

1. **No demo backend.** The app talks only to a kernel. The in-memory mode, the metadata drawer ("Lihat metadata") and the fake settings page are dropped: metadata changes go through the Console and change sets (later S11's Ubah mode). `tools/build_proto.py` stays for `scripts/proto-expected.sh`.
2. **Hash routing** (`#/r/<model>`, `#/r/<model>/<name>`, `#/r/<model>/new`, `#/d/<dashboard>`, `#/approvals`, `#/import/<import>`), so the kernel needs no SPA fallback and deep links survive reloads.
3. **`/` redirects to `/app/`** when `web/app` exists; `/prototype/…` redirects to `/app/` for old links. The Console stays at `/console/`.
4. **`rangka user add`** is added to the CLI (new file `kernel/cmd/rangka/user.go`), calling the existing `auth.EnsureUser`; the live suite needs a `sales_manager` and a `sales_rep` user, and pilot set-up needs the same.
5. **Feature detection, with contract mocks in tests.** Each pilot feature is on only when its endpoint or meta key exists. The Playwright suite runs every scenario: against the real endpoint when present, otherwise against a `page.route` mock that answers exactly the Fixed-interface shapes. `--require-all` makes a mocked feature a failure; the integrator runs that after S2/S3/S5/S6/S7 merge.
6. **Shapes the program plan left open** are fixed in the plan's Fixed interfaces section by this PR (Task 11) and were posted to the shared notes on 3 Nov: approval item, submit-held-for-approval (202), `meta.prints`, `meta.imports`, attachment item, import commit answer, `/auth/me` `orgs` item. Summary in Task 3's Interfaces block.

## Review Focus

- **Session expires while a form is open** (any call answers 401): the sign-in screen appears over the app, and after signing in the user is back on the same route with their unsaved draft intact. Test in Task 4 (`test_session_expiry_keeps_draft`).
- **Double click on Simpan / Ajukan / Setujui / Impor**: exactly one request is sent and one record/approval/import results; buttons are disabled while a request is in flight. Test in Task 6 (`test_double_submit_sends_one_request`).
- **The server disagrees with the client preview** (422 field errors, a rule the browser engine doesn't know, 409 on submit, a total the server computes differently): the server's errors are shown on the fields, and the server's record (totals, number, status) replaces the preview. Test in Task 6 (`test_server_errors_win`).
- **403 `permission_denied`** on a list, a record, an approval or an import (another org's or outlet's records): a clear "Kamu tidak punya akses ke …" state, never a blank screen or a stack trace. Test in Task 5 (`test_forbidden_list_and_record`).
- **Rupiah typed the Indonesian way** (`1.250.000`, `1250000`, pasted `Rp 1.250.000`) and large totals: parsed to the integer 1250000, sent as an integer, shown `Rp 1.250.000`; no `1.25e6` or `,00`. Test in Task 3 (`parseRupiah`) and Task 6 (`test_rupiah_input`).

**Files:**

All requests send `credentials: "include"`.
